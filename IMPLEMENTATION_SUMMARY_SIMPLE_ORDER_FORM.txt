JAVASCRIPT IMPLEMENTATION
================================================================================

Pattern: IIFE (Immediately Invoked Function Expression)
- Encapsulated scope, no global pollution
- Auto-initialization on DOMContentLoaded

Key Functions:
✅ initOrderForm() - Initialize form and event listeners
✅ addHoneypot(form) - Add hidden honeypot field
✅ displayFileInfo(e) - Show selected file name and size
✅ handleSubmit(e) - Main form submission handler
✅ validateForm(data) - Frontend validation
✅ displayErrors(form, errors) - Show field errors
✅ clearErrors(form) - Remove error messages
✅ showMessage(container, text, type) - Show success/error message
✅ clearMessage(container) - Hide message
✅ setLoading(button, loading) - Toggle loading state
✅ clearFileInfo() - Clear file info display

Validation Rules:
- ФИО: required, 2-100 chars
- Email: required, valid email format (/^[^\s@]+@[^\s@]+\.[^\s@]+$/)
- Phone: required, min 10 chars
- Telegram: required, min 5 chars, no @ at start
- Service: required, must select option
- Description: required, 10-2000 chars

Submission Flow:
1. Prevent default form submission
2. Clear previous messages and errors
3. Get form data from all fields
4. Check honeypot (silent success if filled)
5. Validate all fields (frontend)
6. Set loading state (disabled button, spinner)
7. Prepare data for sending
8. Check if file is present
9. Send request:
   - With file: FormData (multipart/form-data)
   - Without file: JSON (application/json)
10. Handle response:
    - Success: show message, reset form, scroll to message
    - Error: show message, keep data, display field errors
11. Clear loading state

NO Dependencies:
❌ No CONFIG usage
❌ No ApiClient class
❌ No OrderFormHandler class
❌ No class inheritance
✅ Plain fetch() API only

USER EXPERIENCE
================================================================================

Success Flow:
1. User fills form
2. User clicks "Отправить заказ"
3. Button shows spinner: "Отправка..."
4. Button is disabled (prevents double-submit)
5. Request sent to /order-submit.php
6. Success message appears: "✅ Спасибо! Мы свяжемся с вами в ближайшее время"
7. Form resets to empty state
8. File info cleared
9. Page scrolls to message
10. Message auto-hides after 10 seconds

Error Flow:
1. User fills form (possibly with errors)
2. User clicks "Отправить заказ"
3. Button shows spinner: "Отправка..."
4. Button is disabled
5. Request sent to /order-submit.php
6. Error message appears: "❌ Ошибка отправки. Попробуйте ещё раз"
7. Form keeps user data (no reset)
8. Field-specific errors show below inputs
9. Error fields have red borders
10. User can fix errors and resubmit

Honeypot Protection:
- If bot fills honeypot field (name="website")
- Form shows success message
- But does NOT send request to backend
- Silently prevents bot spam

Loading State:
- Button text changes to "Отправка..."
- Spinner icon appears (fa-spinner fa-spin)
- Button is disabled during submission
- Loading state clears after response
